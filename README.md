# review-handoff

一套按需调用的通用开发与独立审查提示词，适用于由用户手动搬运材料的跨会话工作流。

开发会话 A 完成实现与必要验证后，在需要独立审查时提醒用户新开会话 B，并生成完整交接提示词；B 输出可直接复制回 A 的报告，A 核实、修复并完成交付。不会自动创建会话，也不会因为安装就将多轮审查加入项目规则。

## 直接作为提示词使用

打开 [PROMPT.md](PROMPT.md)，复制全文到所用 Harness 的新会话，再附上实际任务，例如：

```text
请按上面的工作流开发以下功能：……
需要独立审查时，提醒我手动新开会话，并生成完整交接提示词。
```

助手会按任务范围选择步骤。简单修改可以快速检查；需要独立审查时，先准备可核验的候选与材料，再提醒切换会话。你不需要自己拼接上下文。

## 作为 Skill 使用

在目标平台支持的 Skills 目录内，将仓库克隆为 `review-handoff` 文件夹：

```bash
git clone https://github.com/JackieZzzzzzz/review-handoff-Skill.git review-handoff
```

也可以下载仓库 ZIP，将内容放入名为 `review-handoff` 的 Skill 文件夹，确保其根目录直接包含 `SKILL.md`，不要多嵌套一层仓库目录。

支持 `$skill-name` 调用方式的平台可这样使用：

```text
请使用 $review-handoff 处理以下开发任务：……
```

不同平台的发现目录、加载时机与调用语法可能不同，应使用该平台提供的方式。不支持 Skill 的平台直接使用 `PROMPT.md`，无需其他组件。

## 文件与维护

| 文件 | 用途 |
| --- | --- |
| [SKILL.md](SKILL.md) | 唯一维护源，包含完整操作步骤与会话交接模板 |
| [PROMPT.md](PROMPT.md) | 从 `SKILL.md` 正文生成的纯提示词，不含 YAML 元数据 |
| [agents/openai.yaml](agents/openai.yaml) | Codex 的按需调用设置；其他平台不一定读取此文件 |

更新流程时先修改 `SKILL.md`，再用其 YAML 头部之后的完整正文更新 `PROMPT.md`，保持二者一致。本仓库没有自动生成脚本或自动发布流程。

## 工作方式与验证范围

- 分别处理实现、验证、独立审查、发现核实、修复和交付，不要求每个任务做满全部步骤。
- 审查绑定具体提交或固定材料；无法核实附件与 SHA 的对应关系时，明确限定结论范围。
- 缺少代码时返回补充请求，不把“未开展审查”写成“没有缺陷”。
- 默认最多三轮独立审查，不要求做满；达到上限仍有问题时重新判断范围和方案。
- 工程通过、数据真实性与领域有效性分别说明；不会自动扩大提交、推送、合并或部署权限。

已进行 Skill 格式校验，以及“实现完成后的新会话交接”和“审查者无法访问代码”两组虚构场景检查；不代表各 Harness 已逐一实测，也不保证发现全部缺陷。

设计参考：[How the Claude Code team does code review](https://claude.dev/blog/solving-code-review-at-anthropic/)。本仓库整理的是通用工作流提示词，不需要使用特定模型或审查服务。
